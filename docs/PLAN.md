# 1in8b 人生状态完整记录方案

- 文档版本：1.4
- 日期：2026-11-20
- 状态：1.5.0 已实现并测试，待真实浏览器更新
- 目标版本：记录器 1.5.0
- 当前已安装版本：1.3.0（需更新到 1.5.0）

## 1. 背景

现有记录器已经能记录：

- 每次抉择的全部选项、选择结果
- 手动 / 自动 / 静默自动标记
- 开局设置、每年重心、反思问题
- 游戏时间线、文本快照、死亡总结

本次要补充的是：**可查询的结构化人生状态**，覆盖游戏页面上展示的全部状态，以及游戏后台的完整当前状态。

## 2. 已确认决策

1. **记录深度**：页面可见状态 + 游戏后台完整当前数据
2. **记录频率**：每次游戏保存都记录
3. **存储方式**：方案 B
   - 每次保存都留一张当前状态照片，即使和上一张完全一样
   - 人生历史（人生纪录、年度记录）只存一份
4. **国家资料**：每个国家/语言存一份，状态照片引用
5. **导出用途**：程序 / BI 查询为主
6. **导出格式**：JSONL + CSV
7. **保留策略**：全部保留，不自动清理
8. **过去数据**：不处理，从更新后的当前这一刻开始
9. **空间不足**：先不处理，只提示

## 3. 一句话方案

**每次游戏保存，都记录一张“当前人生状态照片”；照片包含页面可见状态和后台完整当前字段；历史只存一本；每次抉择额外标记选择前和选择后的状态。**

## 4. 记录范围

### 4.1 身份纪录 / 身份卡

- 姓名
- 性别
- 出生年月、出生地
- 居住地、城乡
- 家族根源 / 民族
- 宗教
- 出身家庭
- 学历、就读学校/年级
- 气质
- MRZ
- 语言

### 4.2 状态

- 健康
- 幸福
- 知识
- 人际关系

### 4.3 金钱

- 净资产
- 现金
- 年收入
- 债务
- 房产/资产
- 家庭阶层 / 分位
- 住房情况

### 4.4 家人与关系

- 父母：姓名、年龄、是否在世、关系、工作
- 兄弟姊妹
- 伴侣
- 子女
- 当前同住成员、居住安排

### 4.5 工作与教育

- 职业
- 是否正式工作
- 学校、年级
- 受教育年数
- 当前学习/工作状态

### 4.6 每年重心

- 当前选中的重心
- 全部可选重心
- 手动 / 自动标记

### 4.7 同秒出生的人

- 姓名
- 国家
- 性别
- 当前状态

### 4.8 人生地图

- 当前年龄
- 年度状态记录
- 每年幸福/状态/国家/场景

> 年度记录属于“历史”，只存一份，不随每张状态照片重复。

### 4.9 国家统计

每个国家/语言一份，状态照片引用国家代码：

- 每年出生人数
- 人口
- 平均寿命（女/男）
- 5 岁以下儿童死亡率
- 人均 GDP（PPP）
- 所得吉尼系数
- 都市人口比例
- 从事农业比例
- 预期受教育年数
- 高等教育粗在学率
- 网路使用率
- 总生育率
- 孕产妇死亡率
- HIV 盛行率
- 凶杀率
- 交通事故死亡
- 烟草使用（男/女）
- 医疗费用自付比例
- 18 岁前结婚率（女性）
- 生活满意度

### 4.10 存活曲线

- 国家/性别
- 当前年龄存活率
- 同出生人群存活比例
- 国家平均、世界平均
- 完整曲线数据（能取到就存；取不到则存可见摘要并标记）

### 4.11 抉择上下文

- 抉择 ID
- 题目、问题、正文
- 全部选项
- 最终选择
- 手动 / 自动 / 静默自动
- 选择前状态
- 选择后状态
- 时间、年龄、年份

### 4.12 后台完整当前状态

每次保存时，尽量保留游戏存档中的全部**当前**字段，包括：

- 隐藏数值
- 天赋/气质
- 家庭原始结构
- 经济原始字段
- 教育/工作原始字段
- 关键 flags
- 其他当前状态字段

不重复保存：

- 人生纪录 `log`
- 年度记录 `years`
- 长期历史
- 临时运行队列 `queue` / `pending` / `recent`

这些历史或临时数据单独存一份，状态照片只存当前状态。

### 5.1 主来源：游戏存档

- 身份、状态、钱、家人、工作、教育、重心、地图年度数据、同秒出生的人、后台字段

### 5.2 补充来源：页面展示

- 家人与生活面板
- 同秒出生的人
- 国家统计
- 存活曲线
- 人生地图
- 重心选项

### 5.3 静态缓存：国家资料

- 每个国家/语言存一份
- 状态照片只存国家代码/引用
- 存活曲线同样按国家缓存

## 6. 采集时机

### 6.1 每次游戏保存

- 监听游戏写存档
- 每次写入都生成一张状态照片
- 即使内容与上一张完全一样也保留
- 不去重

### 6.2 每年

- 年龄变化时标记为“每年状态”
- 仍按每次保存记录

### 6.3 每个抉择前

- 普通弹窗：弹窗出现时
- 自动弹窗：自动选择前
- 静默自动：后台捕获到选择时
- 记录“选择前状态”、题目、全部选项

### 6.4 每个抉择后

- 选择完成或自动完成后
- 记录“选择后状态”
- 关联抉择 ID 和最终选择

### 6.5 出生、死亡

- 出生：第一张状态照片
- 死亡：最后一张状态照片 + 总结

## 7. 状态照片结构

```json
{
  "lifeId": "s...",
  "at": "ISO 时间",
  "saveAt": "游戏保存时间",
  "age": 6,
  "year": 2032,
  "reason": "每次保存|每年|抉择前|抉择后|出生|死亡",
  "decisionRef": "抉择 ID 或 null",
  "identity": {},
  "stats": {},
  "money": {},
  "family": {},
  "educationWork": {},
  "focus": {},
  "comps": [],
  "currentYear": {},
  "countryRef": "CHN",
  "survival": {},
  "backend": {},
  "confidence": "high|medium|low",
  "source": "save+page"
}
```

说明：

- `backend` 保存后台完整当前字段
- 历史 `log` / `years` 不放进每张照片
- `countryRef` 指向国家资料缓存
- 抉择前/后照片通过 `decisionRef` 关联

## 8. 存储与保留

- IndexedDB 新增状态照片表
- 国家资料/存活曲线单独缓存
- 每次保存都写入，不去重
- 全部保留，不自动清理
- 面板显示：
  - 状态照片数量
  - 最近一次状态时间
  - 存储占用
  - 每次保存/每年/抉择前/抉择后数量
- 空间不足时提示，但不删除旧数据

## 9. 导出与程序/BI

主格式：

- `1in8b-states.jsonl`
  - 一行一张状态照片
  - 适合 Python、DuckDB、数据库、BI
- `1in8b-states.csv`
  - 常用字段扁平化
  - 适合 Excel/BI
- 国家资料单独导出
- 抉择、时间线、文本快照继续保留

说明：

- 程序/BI 可以按 `lifeId`、`age`、`at`、`reason`、`decisionRef` 查询
- 国家资料用 `countryRef` 关联
- 历史只出现一次，不重复

- 金钱：净资产、收入、债务、房产、家庭阶层
- 家人：父母、兄弟姊妹、伴侣、子女的姓名/年龄/关系/工作

- 手动/自动/静默自动标记
- 历史只存一份，不重复
- JSONL/CSV 可被程序/BI 读取

### 验收标准

1. 测试人生中，游戏每保存一次，状态照片数量就增加一张。
2. 每张照片都包含当前身份、状态、金钱、家人、工作/教育、重心、同秒出生的人、国家引用。
3. 每个抉择都有选择前和选择后照片，并关联题目、全部选项、最终选择。
4. 手动、自动、静默自动可区分。
5. 历史只存一份，不在每张照片中重复。
6. 国家统计/存活曲线按国家只存一份。
7. JSONL/CSV 能正常查询。

## 12. 风险与限制

- 游戏内部完整状态在闭包里，只能读存档 + 页面；不是真正每一次内部 tick。
- 存档写入有延迟；抉择前后状态可能差一个保存间隔。
- 每次保存都记录、全部保留，数据量会很大。
- 监听每次保存需要更深入地接入页面存储，网站大改后可能失效。
- 国家统计/存活曲线是静态/派生数据；完整曲线如果页面不暴露数据，只能存可见摘要。
- 身份卡标签、MRZ、气质/宗教等字段可能随网站版本变化。
- 所有数据只存本机，不上传；包含姓名、家人关系等隐私信息。

## 13. 非目标

- 不补过去的人生结构化状态
- 不生成独立网站或图表查看器
- 只在记录器面板内提供文字列表，不记录图片/图表画面本身
- 不保证每一次内部 tick
- 不自动清理旧数据
- 不上传到服务器

## 14. 执行环境规范（不抢鼠标、不置前）

### 14.1 硬规则

- 不使用用户正在使用的真实 Chrome（`DISPLAY=:0`）做自动化。
- 不执行 `google-chrome <url>` 直接交给现有浏览器会话。
- 不在 `:0` 上执行 `xdotool`、`wmctrl`、`import`、`xwd`。
- 不关闭、不重启、不修改用户真实 Chrome 配置。
- 测试使用独立配置目录，不使用真实 Chrome profile。

### 14.2 Xvfb 虚拟显示

安装：

```bash
sudo apt-get update
sudo apt-get install -y xvfb
```

启动：

```bash
Xvfb :99 -screen 0 1440x900x24 -ac -nolisten tcp &
```

无 sudo 时的替代（本次实际使用）：

```bash
mkdir -p /tmp/1in8b-xvfb-deb /tmp/1in8b-xvfb
cd /tmp/1in8b-xvfb-deb
apt-get download xvfb
dpkg-deb -x xvfb_*.deb /tmp/1in8b-xvfb
/tmp/1in8b-xvfb/usr/bin/Xvfb :99 -screen 0 1440x900x24 -ac -nolisten tcp &
```

所有测试命令显式带 `DISPLAY=:99`：

```bash
DISPLAY=:99 google-chrome \
  --user-data-dir=/tmp/1in8b-xvfb/profile \
  --remote-debugging-port=9222 \
  --no-first-run \
  --no-default-browser-check \
  --disable-gpu \
  --window-size=1440,900 \
  about:blank
```

### 14.3 测试操作

- 页面点击优先走 CDP，不移动真实鼠标。
- 截图只截 `:99`，不截 `:0`。
- 关闭测试环境只结束 `/tmp/1in8b-xvfb/profile` 和 `Xvfb :99` 相关进程。
- 测试数据独立，不写入真实记录器。

### 14.4 真实安装

## 16. 1.4.0 导出整理与删除人生

### 16.1 界面整理

- “所有人生”页保留人生列表和统计
- 导出收进 `导出 / 维护` 折叠区
- 常用导出：全部 JSON、全部抉择 CSV、状态 JSONL
- 更多导出：快照 JSONL、状态 CSV、国家 CSV、重心 CSV、时间线 CSV
- 维护：刷新补录、清空全部
- 提示与诊断默认折叠
- 人生详情底部增加“删除此人生”

### 16.2 删除规则

- 删除整个人生
- 当前人生允许删除；删除后本局停止记录，下一世重新开始
- 永久删除，不可恢复
- 两次确认
- 删除前提醒先导出
- 删除范围：抉择、重心、时间线、文本快照、状态照片、关联临时捕获
- 国家资料共享，不删除

### 16.3 防止补录复活

- 删除时记录 `lifeId` 到 `deletedLifeIds`
- 旧人生结束时间也加入 `l<endedAt>` 墓碑
- 补录、导入、状态捕获、当前人生识别都跳过已删除 ID
- 刷新和“刷新补录”不会把删除的旧人生带回
- 不改游戏自己的存档
- “清空全部”同样写入墓碑

### 16.4 测试

- 删除旧人生：列表消失，刷新补录后不回来
- 删除当前人生：本局停止记录，FAB 归零
- 删除后新人生正常记录
- 清空全部：人生、状态、快照、时间线清零；墓碑保留
- 两次确认
- 导出仍正常
- Xvfb 测试，不移动真实鼠标
